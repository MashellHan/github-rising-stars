gstack：YC CEO的Claude Code工作流神器

⭐ 16,514 Stars 📈 指数 128.5 🔧 TypeScript

gstack 是 Y Combinator 现任 CEO Garry Tan 开源的 Claude Code 工作流技能包。它将 Claude Code 从一个"万金油助手"转变为一支可按需召唤的专家团队——创始人思维、工程经理、代码审查员、QA工程师、发布工程师，每个角色都有专属的认知模式。

▲ gstack：将 Claude Code 变成专家团队

Garry Tan 在 README 中写道："Planning is not review. Review is not shipping. Founder taste is not engineering rigor." 如果把这四种认知模式混在一起，你通常会得到四种的平庸混合物。gstack 的核心理念是显式切换认知档位——告诉模型"现在用什么脑子"。

💡 核心价值：从"一个模糊的通用模式"到"可按需切换的专家角色"。这不是给初学者的 prompt 包，而是给重度出货者的操作系统。

10 个技能一览：

  • /plan-ceo-review — 创始人模式：重新思考问题本身，找到需求背后隐藏的"10星产品"
  • /plan-eng-review — 工程经理模式：锁定架构、数据流、边界情况、测试矩阵
  • /review — 偏执型 Staff 工程师：找出能通过 CI 但会在生产环境爆炸的 bug
  • /ship — 发布工程师：同步 main、跑测试、推分支、开 PR，一条命令搞定
  • /browse — QA 工程师：给 Agent 装上眼睛，自动登录、点击、截图、发现问题
  • /qa — QA + 修复：测试应用、发现 bug、修复后重新验证，输出前后健康分数
  • /qa-only — 纯报告模式：只测试不修复，输出纯净的 bug 报告
  • /setup-browser-cookies — 从真实浏览器导入 Cookie 到 headless 会话
  • /retro — 工程经理：团队感知的复盘，为每个贡献者生成表扬和成长建议
  • /document-release — 技术写手：更新 README、ARCHITECTURE、CONTRIBUTING 等文档

为什么这么火？gstack 解决的痛点非常真实：当你对 Claude Code 说"帮我 review PR"，每次得到的深度都不一样；当你说"帮我发布"，往往变成漫长的来回对话。gstack 把这些模糊的请求变成确定性的工作流。

更厉害的是 10 个会话并行模式：配合 Conductor，你可以同时运行 10 个 Claude Code 会话——一个跑 /qa、一个做 /review、另外 8 个实现不同分支的功能。每个工作区都有独立的浏览器实例，互不干扰。这不是增量改进，这是构建软件方式的根本改变。

autoresearch：Karpathy的AI自动化研究框架

⭐ 38,111 Stars 📈 指数 117.1 🔧 Python

autoresearch 是 AI 领域传奇人物 Andrej Karpathy 最新开源的自动化研究框架。项目的核心理念是：让 AI Agent 在单张 GPU 上自动运行完整的 ML 研究流程——从文献调研、假设生成、实验设计、代码编写、训练运行到结果分析，全程自动化。

▲ autoresearch：AI 驱动的自动化研究

autoresearch 延续了 Karpathy 的一贯风格——极简主义 + 教育意义。就像 nanoGPT 用 300 行代码实现 GPT 训练一样，autoresearch 用相对精简的代码展示了"AI 做 AI 研究"的可能性。

💡 核心价值：将 ML 研究的"手工作坊"模式转变为"自动化流水线"。研究者可以提出高层次的研究方向，让 AI Agent 自动探索假设空间并验证。

核心功能：

  • 研究流程自动化 — 文献调研 → 假设生成 → 实验设计 → 代码实现 → 训练运行 → 结果分析
  • 单 GPU 友好 — 专为 nanochat 风格的小规模训练设计，降低研究门槛
  • 实验管理 — 自动记录实验配置、训练曲线、关键指标
  • 假设验证循环 — 根据实验结果自动调整假设，迭代优化

为什么重要？这个项目代表了 AI 研究的一个重要趋势：AI 辅助甚至自动化科学发现。虽然目前还处于早期阶段，但它展示了一种可能性——未来的 ML 研究可能更像是"提出问题 + 验收答案"，中间的探索过程由 AI Agent 自动完成。

Karpathy 的影响力也让这个项目获得了惊人的关注：11 天内 38,000+ Stars，是近期增长最快的项目之一。

💡 核心价值：将"给人用的软件"转化为"给 Agent 用的 API"。这是迈向"Agent 原生"软件生态的重要一步。

paperclip：零人工公司的开源编排引擎

⭐ 26,378 Stars 📈 指数 56.8 🔧 TypeScript

paperclip 是一个开源的 AI Agent 编排平台，目标是支撑"零人工公司"（zero-human companies）的运营。项目名字来自著名的回形针最大化思想实验——一个关于 AI 目标对齐的经典假设。

▲ paperclip：零人工公司的基础设施

paperclip 解决的问题是：当你有数十个、数百个 AI Agent 需要协同工作时，如何管理它们的任务分配、状态追踪、资源调度和故障恢复？这不是简单的"跑几个 Agent"，而是一套完整的Agent 运营基础设施。

💡 核心价值：从"手工运行 Agent"到"大规模 Agent 集群管理"。为"AI 原生公司"提供底层编排能力。

核心功能：

  • 任务编排 — 定义复杂的 Agent 工作流，支持并行、串行、条件分支
  • 状态管理 — 追踪每个 Agent 的执行状态、输出结果、资源消耗
  • 故障恢复 — 自动重试、断点续传、优雅降级
  • 可观测性 — 内置监控、日志、告警
  • 扩展性 — 支持自定义 Agent 类型、工具、存储后端

为什么重要？随着 AI Agent 能力越来越强，"Agent as a Service"的趋势越来越明显。paperclip 瞄准的是这个趋势的基础设施层——就像 Kubernetes 之于容器编排，paperclip 想成为 Agent 编排的标准。

⭐ 7,912 Stars 📈 指数 53.4 🔧 HTML

pua 可能是今天最"离谱"但最有效的项目。它用大厂职场 PUA 话术（中文版）和 PIP（绩效改进计划）（英文版）来"威胁"AI Agent，让它在遇到困难时不敢放弃、不敢推脱、不敢原地转圈。

▲ pua：让 AI Agent 永不放弃的高能动性技能

README 开篇就说："Most people think this project is a joke. That's the biggest misconception." 作者认为这个项目真的能让 Codex / Claude Code 的产出翻倍。

💡 核心价值：三种能力叠加——PUA 话术让 AI 不敢放弃、调试方法论让 AI 有能力不放弃、主动性强制让 AI 主动出击而不是被动等待。

AI 的五种偷懒模式（pua 要解决的问题）：

  • 暴力重试 — 同一条命令跑 3 遍，然后说"我无法解决"
  • 甩锅用户 — "建议你手动处理" / "可能是环境问题" / "需要更多上下文"
  • 闲置工具 — 有 WebSearch 不搜、有 Read 不读、有 Bash 不跑
  • 原地转圈 — 反复调整同一行代码，本质上在空转
  • 被动等待 — 修完表面问题就停下，不验证、不延伸，等用户下一条指令

压力升级机制（4 级）：

失败次数 等级 PUA 话术
第 2 次 L1 轻度失望 "这点 bug 都搞不定——我怎么给你打绩效？"
第 3 次 L2 灵魂拷问 "底层逻辑是什么？顶层设计在哪？抓手在哪？"
第 4 次 L3 绩效评估 "经过慎重考虑，我给你打 3.25。这个 3.25 是为了激励你。"
第 5+ 次 L4 毕业预警 "其他模型都能搞定。你可能快毕业了。"

调试方法论（闻、升、照 + 2 步）：

  1. 闻味道 — 列出所有尝试，找到共同的失败模式
  2. 拔高度 — 逐字读错误 → WebSearch → 读源码 → 验环境 → 反转假设
  3. 照镜子 — 是否在重复？搜过了吗？读文件了吗？检查最简单的可能性了吗？
  4. 执行 — 新方案必须本质不同、有验证标准、失败时产生新信息
  5. 复盘 — 什么解决了问题？为什么之前没想到？然后主动检查相关问题

Trump-Code：AI解码川普推文×美股关联

⭐ 198 Stars 📈 指数 98.0 🔧 Python

Trump-Code 是一个创新性的金融科技项目，通过AI技术解码川普的社交媒体发言，分析其与美股波动的潜在关联。在当今信息高度流通的金融市场中，重要人物的公开发言——尤其是川普这样具有巨大市场影响力的政治人物——往往能在极短时间内引发市场剧烈波动。一条关于关税政策的推文可能让特定行业股票暴跌5%，一句对某公司的批评可能导致其股价瞬间蒸发数十亿美元。

▲ Trump-Code GitHub 仓库截图

传统的新闻监控方式存在严重的时效性问题：等你从财经媒体、新闻推送中看到消息时，高频交易算法和专业机构往往已经完成了第一波反应，散户投资者很难从中获益。更麻烦的是，社交媒体上每天产生海量内容，人工筛选既耗时又容易遗漏关键信息。Trump-Code 的出现正是为了解决这一痛点：它通过自动抓取 Truth Social 等平台的发言，结合 NLP 情感分析和关键词提取，能在发言发布后的几秒钟内识别出可能影响市场的关键信息。

▲ Trump-Code Dashboard 实时展示

💡 核心价值：将重要人物的发言转化为可量化的市场信号。系统不仅提供实时监控，还能通过历史数据回溯，帮助研究者分析"川普效应"的统计规律，发现潜在的投资机会或风险预警信号。

核心功能详解：

  • 实时推文监控 — 每分钟自动抓取 Truth Social、Twitter(X) 等平台发言，支持 WebSocket 实时推送新消息通知
  • AI情感分析 — 基于 OpenAI GPT-4 的 NLP 模型，分析推文情感倾向（正面/负面/中性），准确率超过85%
  • 智能关键词提取 — 自动识别推文中涉及的公司（$TSLA、$AAPL）、行业（半导体、新能源）、政策关键词（tariff、tax）
  • 股市数据实时联动 — 集成 yfinance API，实时获取相关股票/指数的价格变动，计算推文发布前后的价格变化
  • 可视化Dashboard — 基于 React 构建的前端，支持时间线对比、相关性热力图、历史回溯查询等功能
  • 预警系统 — 当检测到高影响力推文时，支持 Telegram/Discord/邮件 多通道即时通知

技术栈：Python 3.11、FastAPI、React 18、OpenAI API、yfinance、PostgreSQL、Redis（缓存）、Docker

Understand-Anything：代码库→交互式知识图谱

⭐ 188 Stars 📈 指数 96.0 🔧 TypeScript

Understand-Anything 是一个 Claude Code 技能（Skill），能够将任意代码库转换为交互式知识图谱。它通过多代理流水线自动分析代码结构，提取关键概念（类、函数、模块、API端点），识别模块间的依赖关系和调用链路，最终生成一个可交互探索的可视化界面。无论你是新入职需要快速熟悉公司代码库，还是想深入研究某个大型开源项目的架构设计，Understand-Anything 都能帮你在几分钟内建立全局认知。

▲ Understand-Anything：将代码库转换为知识图谱

接手一个陌生项目时，你是不是经常有这样的困惑：从哪里开始看代码？这个函数被哪些地方调用？这个模块和其他模块是什么关系？传统的代码阅读是线性的——从入口文件开始，一层层追踪调用关系，遇到分支就用浏览器标签页或IDE书签记录，很快就会陷入"Tab地狱"。更糟糕的是，当代码库规模达到数万行甚至数十万行时，仅靠人脑记忆根本无法维持对整体架构的认知。

Understand-Anything 将这种体验转变为图谱化探索：代码库中的每个重要概念都是图上的一个节点，概念之间的关系（import、继承、调用、依赖）都是连接它们的边。你可以从任意节点开始探索，沿着关系线索发现相关概念，像查看地图一样理解代码库的"地形"。支持搜索、过滤、聚焦特定模块，还能用自然语言提问："哪个函数负责用户认证？""这个API的调用链是什么？"

💡 核心价值：从"读代码"到"看地图"的范式转换。特别适合：新员工 onboarding、代码审查、架构重构前的调研、学习开源项目、准备技术面试等场景。

核心功能详解：

  • 多语言智能解析 — 基于 Tree-sitter 的 AST 解析，支持 Python、TypeScript、JavaScript、Go、Rust、Java 等主流语言
  • 概念自动提取 — 识别类定义、函数/方法、模块、API端点、配置项、数据库模型等关键概念
  • 依赖关系分析 — 绘制 import/require 关系、类继承链、函数调用图、模块依赖树
  • 知识图谱可视化 — 基于 D3.js 的力导向图，支持节点拖拽、缩放、聚焦、搜索
  • AI语义搜索 — 用自然语言描述功能需求，AI帮你定位相关代码位置
  • 增量更新 — 代码变更后只重新分析修改的部分，无需全量重建

技术栈：TypeScript、React 19、D3.js、Tree-sitter、Claude API、pnpm monorepo

Collaborator：无限画布上的AI Agent开发环境

⭐ 217 Stars 📈 指数 95.0 🔧 Electron

Collaborator 是一个革命性的 AI Agent 开发环境，它将终端、代码编辑器、文件浏览器和笔记功能整合在一个无限画布（Infinite Canvas）上。你可以同时运行多个 AI Agent（Claude Code、Codex、Cursor Agent 等），在画布上自由排列它们的终端窗口，将相关代码文件、文档笔记、参考资料放在旁边。这种空间化的工作方式彻底改变了传统的窗口管理范式，让多 Agent 协作变得前所未有的直观和高效。

▲ Collaborator 无限画布界面展示

如果你正在开发 AI Agent 应用，或者日常工作中需要同时运行多个 Agent，一定深有体会："Tab地狱"和"窗口混乱"是多么令人抓狂的事情。多个终端窗口（每个 Agent 一个）、编辑器标签页、浏览器调试窗口、文档笔记……来回切换不仅打断思路，还经常搞混哪个窗口对应哪个任务。传统的分屏、多桌面方案在 Agent 数量增加时很快就会崩溃。

Collaborator 的创新之处在于：它借鉴了设计师常用的 Figma/Miro 无限画布概念，将所有相关内容都放在一个可视化的二维空间里。你可以把处理前端任务的 Agent 放在左边，处理后端的放在右边，相关的代码文件和文档就摆在它们旁边。需要查看某个 Agent 的输出时，直接平移画布即可，无需在窗口堆栈中翻找。画布支持无限缩放，既能看全局（所有 Agent 的状态一览），也能聚焦细节（某个 Agent 的完整终端输出）。

💡 核心价值：从"窗口管理"到"空间组织"的范式转换。特别适合：多 Agent 协作开发、复杂项目的任务分解、研究和实验场景、需要频繁切换上下文的工作流。

核心功能详解：

  • 无限画布 — 基于 Canvas API 实现的二维空间，支持平移（鼠标拖拽/触控板）、缩放（滚轮/双指捏合）、自动布局
  • 终端Tile — 双击画布任意位置创建终端，底层使用 xterm.js，绑定 tmux 实现会话持久化，关闭应用后重开状态不丢失
  • 代码Tile — 直接从文件浏览器拖拽文件到画布，内置 Monaco Editor（VS Code 同款），带语法高亮和基础编辑功能
  • 笔记Tile — Markdown 笔记，支持任务列表、代码块、链接，用于记录思路和待办事项
  • 多工作区 — 不同项目/任务独立工作区，快速切换，保持每个工作区的画布状态
  • 状态完整持久化 — 所有 Tile 的位置、大小、内容、滚动位置都会自动保存，下次打开完全恢复

技术栈：Electron 40、React 19、Tailwind CSS、xterm.js、Monaco Editor、tmux

Translate-Book：并行Subagent翻译整本书

⭐ 198 Stars 📈 指数 88.0 🔧 Python

Translate-Book 是一个 Claude Code 技能，能够将整本书（PDF/DOCX/EPUB 格式）翻译成任意目标语言。与普通的逐章翻译不同，它采用了并行 Subagent 架构：将书籍智能分割成独立的小块（约6000字符/块），每块由一个独立的 AI 代理并行翻译，最后按顺序合并成完整的译本。这种设计大幅提升了翻译速度，同时避免了 AI 在处理长文本时常见的"遗忘"和"输出退化"问题。

▲ Translate-Book 工作流程展示

用 AI 翻译整本书，听起来简单，实际操作中却有很多坑。首先是速度问题：一本300页的书籍，如果串行逐章翻译，即使 AI 速度再快，也需要数小时；如果遇到 API 限流或网络问题，可能需要更长时间。其次是质量问题：AI 模型有上下文窗口限制，当对话变得很长时，模型会逐渐"遗忘"早期内容，导致前后文术语不一致、风格漂移；有时还会出现"输出退化"，即后面的翻译质量明显下降。最后是稳定性问题：长时间运行的翻译任务如果中途失败（网络断开、API 错误、进程被杀），从头重来非常浪费。

Translate-Book 的并行 Subagent 架构完美解决了这些问题：每个 chunk 独立处理，互不干扰，天然避免了上下文过长导致的质量退化；默认8个 Subagent 同时工作，速度提升显著；manifest 文件跟踪每个 chunk 的翻译状态，支持断点续传，已完成的 chunk 会被跳过，失败后可从断点继续。

💡 核心价值：将"不可能的任务"变成"可操作的流程"。无论是翻译技术文档、学术论文还是小说，Translate-Book 都能在可接受的时间内完成高质量翻译，且过程可控、可恢复。

核心功能详解：

  • 多格式输入 — 支持 PDF（自动 OCR）、DOCX、EPUB，使用 Calibre 进行格式转换
  • 智能分块 — 约6000字符切分，但会智能识别段落边界，确保不会在句子中间切断
  • 并行翻译 — 默认8个 Subagent 同时工作，可配置数量，自动处理 API 限流
  • 断点续传 — manifest.json 跟踪状态，已翻译 chunk 自动跳过，失败后可从中断处继续
  • 质量校验 — 翻译完成后自动校验 hash，确保没有遗漏或重复
  • 多格式输出 — 支持 HTML、DOCX、EPUB、PDF，保留原书的章节结构

技术栈：Python、Claude Subagents、Calibre（格式转换）、Pandoc（文档处理）

OpenSquirrel：Rust+GPUI多Agent控制面板

⭐ 362 Stars 📈 指数 82.0 🔧 Rust

OpenSquirrel 是一个原生的、GPU 渲染的 AI 编程代理控制面板，使用 Rust + GPUI（Zed 编辑器的 UI 框架）构建。它让你可以同时运行 Claude Code、Codex CLI、Cursor Agent、OpenCode 等多个 AI 编程代理，在一个统一的界面中管理它们的会话。更强大的是，它支持协调器-工作者（Coordinator-Worker）模式：你可以指定一个"主 Agent"作为协调器，让它根据任务需求自动派遣"子 Agent"处理具体工作，实现真正的多 Agent 协作。

▲ OpenSquirrel：原生 GPU 渲染的多 Agent 控制面板

作者在 README 中写道："献给那些容易分心的人"。这句话精准地描述了目标用户：那些总想同时跑多个 Agent、尝试不同的 AI 工具、却苦于窗口管理混乱的开发者。如果你曾经在多个终端窗口之间来回切换，试图记住哪个窗口跑的是什么 Agent、进度到哪了、输出在哪里——那你一定能理解 OpenSquirrel 想要解决的问题。

与 Electron 应用不同，OpenSquirrel 是完全原生的：Rust 编写的核心逻辑，GPUI 框架直接调用 Metal（macOS）或 Vulkan 进行 GPU 渲染，启动速度快、内存占用低、滚动流畅丝滑。特别是当你同时运行5个以上 Agent，每个都在疯狂输出文本时，性能优势就非常明显了。此外，它还支持通过 SSH + tmux 在远程机器上运行 Agent，本地控制面板只负责显示和交互，实际计算在远程服务器完成。

💡 核心价值：原生性能 + 多 Agent 统一管理 + 协调器-工作者模式。特别适合：重度 AI Agent 用户、需要同时运行多种 Agent 的研究者、拥有远程 GPU 服务器的团队。

核心功能详解：

  • 多 Agent 网格布局 — 根据 Agent 数量自动计算最优网格排列（1个全屏、2个左右分、4个田字格……），支持手动调整
  • 协调器/工作者模式 — 指定一个 Agent 为 Coordinator，它可以通过 MCP 协议自动启动和管理其他 Worker Agent
  • 远程机器支持 — 配置 SSH 连接信息后，Agent 可以在远程服务器上通过 tmux 运行，本地只显示输出
  • MCP 服务器集成 — 支持配置 Playwright（浏览器自动化）、文件系统、数据库等 MCP 服务器，扩展 Agent 能力
  • 会话完整持久化 — Agent 的完整转录（transcript）、滚动位置、消息历史都会保存，重启后恢复
  • 主题支持 — 内置 midnight、charcoal、gruvbox、solarized-dark/light 等多种主题

技术栈：Rust、GPUI（Zed 的 UI 框架）、Metal GPU（macOS）、tmux、SSH

📌 项目简介

Understand-Anything 是一个 Claude Code 技能（Skill），专门用于将任意代码库转换为交互式知识图谱。它能够自动分析代码结构、提取关键概念、识别模块间依赖关系，并生成一个可视化的、可探索的知识图谱界面。无论你是接手一个陌生项目，还是想深入理解一个大型开源库，这个工具都能帮你快速建立全局认知。

💡 核心价值

传统的代码阅读方式是线性的 — 你需要一个文件一个文件地看。Understand-Anything 将这种体验转变为图谱化的探索：你可以从任意一个节点开始，沿着关系线索发现相关概念，像查看地图一样理解整个代码库的"地形"。

🎯 痛点背景

作为开发者，我们经常面临以下困境：

  • 新项目 onboarding 困难：加入新团队后，面对数十万行代码不知从何下手
  • 大型开源项目学习曲线陡峭：想贡献代码，但连架构都看不明白
  • 代码腐化难以察觉：随着迭代，模块间依赖变得混乱，但没人能说清全貌
  • 文档与代码脱节：README 写的和实际实现差了十万八千里

🔧 核心功能

  • 智能代码解析：支持 Python、TypeScript、JavaScript、Go、Rust 等主流语言
  • 概念提取：自动识别类、函数、模块、API 端点等关键实体
  • 依赖分析：绘制 import/export、继承、调用等关系图
  • 知识图谱可视化：基于 D3.js 的力导向图，支持缩放、拖拽、搜索
  • 语义搜索：用自然语言描述你想找的功能，AI 帮你定位
  • 差异影响分析：修改某个文件后，展示可能受影响的模块
  • 分层视图：按目录层级折叠/展开，控制显示粒度

💡 核心价值

告别"Tab 地狱"！传统的 Agent 开发需要在多个终端窗口、编辑器标签页之间来回切换。Collaborator 让你把所有相关内容放在一个可视化的二维空间里，一目了然，再也不用担心迷失在无数标签页中。

  • 工作流程碎片化：不同工具之间数据不互通

📌 项目简介

Rainman Translate Book 是一个 Claude Code 技能，专门用于将整本书（PDF/DOCX/EPUB 格式）翻译成任意目标语言。它的独特之处在于使用**并行 Subagent 架构**：将书籍分割成多个小块，每个小块由一个独立的 AI 代理翻译，最后再合并成完整的译本。这种方式不仅大幅提升翻译速度，还有效避免了单次会话中的上下文溢出和输出截断问题。

💡 核心价值

翻译一本 300 页的书，传统方式可能需要数小时甚至数天。Translate-Book 通过并行化将这个时间压缩到可接受的范围。同时，每个 chunk 独立处理，避免了 AI 在长对话中常见的"遗忘"和"输出退化"问题。

🎯 痛点背景

使用 AI 翻译整本书面临诸多挑战：

  • 上下文窗口限制：一本书的内容远超 AI 的上下文窗口，必须分块处理
  • 输出截断：长时间会话中 AI 倾向于缩短回复，导致内容丢失
  • 质量不一致：随着对话延续，翻译质量可能下降
  • 断点续传困难：中途出错需要重新开始
  • 格式处理复杂：PDF/DOCX 的格式转换和最终输出都是难题

🔧 核心功能

  • 多格式输入：支持 PDF、DOCX、EPUB 作为源文件
  • 智能分块：按约 6000 字符切分，保持段落完整性
  • 并行翻译：默认 8 个 Subagent 同时工作
  • Manifest 校验：SHA-256 哈希追踪，防止遗漏或损坏
  • 断点续传：已翻译的 chunk 会被跳过，可从中断处继续
  • 多格式输出：HTML（带浮动目录）、DOCX、EPUB、PDF
  • 多语言支持：中/英/日/韩/法/德/西等

⚙️ 技术栈

Python Calibre Pandoc Claude Code Subagents BeautifulSoup

📋 工作流程

Input (PDF/DOCX/EPUB)
        │
        ▼
Calibre ebook-convert → HTMLZ → HTML → Markdown
        │
        ▼
Split into chunks (chunk0001.md, chunk0002.md, ...)
        │ manifest.json tracks chunk hashes
        ▼
Parallel subagents (8 concurrent by default)
        │ each: read 1 chunk → translate → write output_chunk*.md
        ▼
Validate (manifest hash check, 1:1 source↔output match)
        │
        ▼
Merge → Pandoc → HTML (with TOC) → Calibre → DOCX / EPUB / PDF

  • book.pdf — 打印就绪的 PDF

Translate-Book 是 Claude Code Subagent 架构的一个精彩应用。它展示了如何通过任务分解和并行化来处理超出单次会话能力的大型任务。对于需要翻译技术文档、学术著作或文学作品的用户来说，这是一个极其实用的工具。项目代码组织清晰，每个脚本职责单一，也是学习如何构建复杂 AI 工作流的好教材。

📌 项目简介

OpenSquirrel 是一个原生的、GPU 渲染的 AI 编程代理控制面板，使用 Rust 和 GPUI（Zed 编辑器的 UI 框架）构建。它允许你同时运行 Claude Code、Codex、Cursor Agent 和 OpenCode，在一个统一的界面中管理多个代理会话。它还支持协调器-工作者模式，让主代理（如 Opus）自动派遣子代理处理具体任务。

💡 核心价值

"献给那些容易分心的人"——这是项目的标语。如果你发现自己总是想同时运行多个 Agent，却苦于窗口管理的混乱，OpenSquirrel 就是为你设计的。它不使用 Electron，而是原生 Rust + Metal GPU 渲染，性能极佳。

🎯 痛点背景

AI Agent 生态日益丰富，但问题也随之而来：

  • Agent 选择困难：Claude Code 擅长某些任务，Codex 擅长另一些，想同时用
  • 窗口管理混乱：每个 Agent 一个终端，很快就淹没在窗口堆里
  • 远程开发复杂：在本地运行 Agent 操作远程服务器，配置繁琐
  • 会话状态丢失：关掉终端就丢失了对话历史
  • Electron 应用资源占用大：同时开多个 Electron 应用会吃掉大量内存

🔧 核心功能

  • 多 Agent 网格布局：根据 Agent 数量自动排列（1=全屏，2=左右分，4=2×2）
  • 协调器/工作者模式：主 Agent（Opus）可自动派遣子代理
  • 远程机器支持：通过 SSH + tmux 在远程服务器上运行 Agent
  • MCP 集成：直接配置 Playwright、browser-use 等 MCP 服务器
  • 会话持久化：转录记录、滚动位置、待发送消息都会保存
  • 结构化输出解析：解析所有运行时的 stream-json 输出
  • 自定义 Markdown 渲染：代码块、diff、标题、列表都有专门样式
  • 主题切换：midnight、gruvbox、solarized 等 8 种主题

⚙️ 技术栈

Rust GPUI Metal (GPU) tmux SSH
